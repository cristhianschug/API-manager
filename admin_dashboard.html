Catálogo Firebird
Por que capturar o catálogo?
O catálogo lê o dicionário de dados do Firebird (RDB$RELATIONS, RDB$PROCEDURES, RDB$TRIGGERS) e armazena um snapshot JSON vinculado a este cliente. Esse snapshot é enviado automaticamente como contexto nas requisições de IA (/api/v1/ai/*), permitindo que os agentes conheçam o modelo de dados real sem documentação manual.

Como os agentes usam o catálogo sem configuração adicional

Os agentes de IA inferem utilidade diretamente dos nomes das tabelas e procedures — sem que o administrador precise descrever cada uma. Exemplos do que é inferido automaticamente:

  • Tabelas com prefixo TB → entidades principais do ERP (clientes, pedidos, produtos…). O agente sabe quais recursos existem e pode sugerir endpoints ou queries.
  • Procedures com verbos (ex.: SP_FECHAR_OS, SP_CALCULAR_SALDO) → indicam operações de negócio disponíveis no banco, que podem ser expostas como ações da API.
  • Triggers → revelam regras automáticas do banco (ex.: auditoria, recálculo de saldo), evitando que o agente sugira lógica duplicada na aplicação.
  • Ausência de tabelas → o agente evita sugerir funcionalidades que o banco não suporta (ex.: não há TBAGENDA → não existe módulo de agenda).

O snapshot é re-capturado sempre que o banco evoluir. Enquanto não for recapturado, os agentes usam a versão anterior.
