# Security Rules

Status: DRAFT

1. Never use SYSDBA for API runtime.
2. Never expose arbitrary SQL.
3. Never accept a database path from a client.
4. Never accept Firebird credentials from a client.
5. Never accept an arbitrary tenant identifier as authority.
6. Never share database connections across tenants.
7. Never expose secrets.
8. Never expose sensitive fields by default.
9. Never publish unknown objects automatically.
10. Never expose stack traces.
11. Never trust Swagger as a security boundary.
12. Never bypass authorization for internal-looking endpoints.
13. Never weaken tenant isolation for performance.
14. Never claim security based only on code review; execute security tests.
