# Decision Log

Status: DRAFT

## Format

Every material architectural decision should record:

- ID
- Date
- Status
- Context
- Decision
- Alternatives
- Consequences
- Evidence
- Approver

## Decisions

### ADR-001 — Separate Control Plane and Data Plane

Status: PROPOSED

Decision: Keep administration/configuration separate from request execution.

Reason: Prevent administrative storage from becoming a mandatory hot-path dependency.

### ADR-002 — Initial API is Read-Only

Status: PROPOSED

Decision: Start with GET/read capabilities.

Reason: Writes can trigger complex ERP business rules and require stronger validation.

### ADR-003 — No Arbitrary SQL

Status: PROPOSED

Decision: Public clients cannot submit arbitrary SQL.

Reason: Prevent data leakage, injection, uncontrolled resource consumption, and tenant escape.

### ADR-004 — API Contract Independent from Database Schema

Status: PROPOSED

Decision: Use DTOs and explicit endpoint contracts.

Reason: Database evolution must not silently break external consumers.

### ADR-005 — Unknown Objects Are Not Published

Status: PROPOSED

Decision: Unknown or ambiguous objects remain unavailable until reviewed.

Reason: Prevent accidental exposure of internal or sensitive behavior.
